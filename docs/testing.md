# 测试说明

本文记录扫描、分类、查重、授权、计划、文件执行与日志恢复的检查方法和结果。

## 实现内容

Cargo workspace 包含 `file-tidy-core`、`file-tidy-platform`、`file-tidy-cli`。core 与 CLI 均使用 `forbid(unsafe_code)`；挂载表与 Windows API FFI 位于 platform，每处 unsafe 均有安全不变量说明。

功能包括多根或逐本地卷扫描、有界并行元数据/类型识别/哈希、取消与聚合进度、八类 TOML 分类、UTC 修改年月、项目整体标记、大小 Top N、目录聚合、陈旧与重复报告、逐项跳过原因和 JSON 无损路径编码。报告输出到 stdout，进度输出到 stderr。

内容读取策略：

- 敏感项仅采集元数据；元数据阶段结束后，将已知敏感文件身份传播到本次清单中的硬链接别名。
- 敏感目录按路径及目录身份识别，覆盖 macOS Data 卷别名；内容读取前重新核验。
- 先检查本地性、挂载、卷身份和节点类型，再通过逐级 no-follow 目录句柄枚举，检查范围包括文件和目录 bind mount。
- 内容读取前核对原生文件身份、类型、大小和修改时间，读取后复核文件句柄及路径。FIFO、socket、设备、链接、reparse、云占位和非本地文件系统均跳过内容读取。
- 普通文件按大小、64 KiB 首段和完整 BLAKE3 分组；硬链接按身份去重，变化的候选记录原因并排除。
- 配置文件读取经过本地性、无链接、敏感区及 1 MiB 大小检查。

## 扫描与平台覆盖

- Linux 挂载表现在保留 mount ID、parent ID，按当前可见拓扑选择叠加挂载并排除被遮蔽的后代；无法判明的拓扑拒绝读取。用 Local→Remote、Remote→Local、隐藏子挂载和歧义图夹具覆盖，避免旧的本地记录掩盖当前网络挂载。[Linux mountinfo 语义](https://www.man7.org/linux/man-pages/man5/proc_pid_mountinfo.5.html)。
- Linux 设备号与文件系统根坐标参与区域判断，覆盖敏感子目录、`.env` 文件及根下其他设备的 bind 别名。坐标只用于策略比较，不用作打开文件的路径；测试为构造的挂载表，没有连接远程盘或挂载真实设备。
- Windows 保留并优先用卷 GUID 根建立扫描任务，避免仅有目录挂载或没有盘符的卷被遗漏；只接受格式受限的卷 GUID namespace，保持 reparse/UNC/设备过滤。系统目录标签也按已知目录身份补充匹配，点文件加入隐藏标记。Windows 原生层已通过交叉编译与 Clippy 检查，原生运行场景列入 Windows CI。
- Unix 祖先句柄使用 Linux `O_PATH` / macOS `O_SEARCH`，不再额外要求祖先可列举；叶子内容保持只读、no-follow。已在本机实测 0111 父目录中的可读文件与可列举子目录。
- 目录枚举逐项检查取消，移除平台内多余排序；核心收到取消不会误报普通 I/O 错误。平台测试在条目之间触发 Interrupted；core 集成测试验证公开扫描边界的取消结果。慢盘性能场景单独验证。
- 已枚举目录按原生身份识别别名，单链接文件别名不再重复计数；真正的不同硬链接目录项仍保留。目录/文件大小写用例按实际原生身份断言，不把大小写敏感卷当作不敏感卷。本机运行了不敏感卷分支，敏感卷原生分支尚未实测。
- 收集到敏感目录或文件的别名证据后，在首次读取内容前更新标签，避免去重抹掉敏感证据；增加目录身份保护和缓存失效回归。
- 分类补充 ODF/旧 Office MIME；PNG 改名 JPG 等同类别格式冲突不再标为一致。ZIP 承载的 APK、Office、ODF 等保留具体后缀分类，但证据只标 Extension；合法 jpg/jpeg、tif/tiff 别名不误报冲突。分类模块 14 项测试及独立 CLI 夹具已运行。

## CLI 验证

对仓库的 config、docs 目录使用默认 TOML 输出 JSON 报告：退出码 0，扫描完成。复查命令：

```sh
cargo run --locked -p file-tidy-cli -- scan config docs \
  --rules config/default-rules.toml --format json --quiet
```

对本地卷执行 `--metadata-only --max-entries 32`：退出码 3，`limit_reached = true`、`complete = false`，扫描内容打开次数及读取字节数均为 0。

参数与退出码见[使用说明](usage.md)。

## 授权与计划检查

授权与计划集成测试使用独立于系统保护区、敏感区和现有项目的夹具根。在 CI 中，夹具位于仓库目录的同级目录。

```sh
FILE_TIDY_TEST_ROOT=/absolute/isolated/fixtures cargo test --workspace --locked \
  --lib --test authorization_plan --test plan_cli --test execution --test rename --test case_rename --test copy --test staging --test tree_copy --test quarantine --test undo --test permanent \
  -- --include-ignored
```

测试覆盖零写入预览、私有状态初始化、持久与会话授权、撤销、目录替换、完整清单、隐藏项、冲突目标、选择变更、敏感许可、永久删除确认、过期、并发锁和 CLI 非交互拒绝。macOS 与 Windows 默认跳过依赖独立夹具的用例，由上述命令显式运行。

Windows 原生状态目录通过相对父句柄创建，采用当前用户专用的可继承 DACL；Unix 使用 0700 目录与 0600 状态文件。打开已有存储时重新核验所有者、权限、链接数与对象身份。

## 执行与日志检查

文件执行测试覆盖同父目录批量移动、完整目录清单、目标被占用、来源父目录换壳、确认后新增子项、取消、符号链接、意图日志失败和结果日志失败。日志失败注入使用 SQLite 触发器，分别验证文件操作前停止，以及文件已移动后的待恢复结果和后续项停止。

名称拼写调整测试覆盖两步预览与执行、完整父目录枚举、真实硬链接冲突、临时位置占用，以及第一步完成后的目标抢占与取消。

平台测试覆盖原生无覆盖重命名、文件身份保持、无内容读取权限文件、目录与链接、父目录替换、提交瞬间的目标占位和来源替换，以及移动后同步错误。Unix 使用目录句柄相对的 rename；Windows 使用源对象句柄。Windows 分支已通过交叉编译与 Clippy，原生行为由 Windows CI 验证。

恢复测试核对未提交意图、已迁移目录、缺少意图的外部移动、变化或歧义对象、撤销授权和快照篡改，并验证诊断不写入状态库或用户目录。CLI 的真实终端检查覆盖状态初始化、授权、确认后移动、敏感项重命名、历史列表与恢复诊断。


## 校验复制检查

复制测试覆盖授权区外的只读源、多块数据与空文件、同父目录批量复制、修改时间与私有权限、敏感内容逐项许可、暂存损坏、源变化、目标竞态和取消。日志触发器分别在创建结果、发布意图和发布结果处注入故障，核对未知归属暂存、已校验暂存及已发布副本的只读恢复状态。日志保存指纹、长度和哈希。


目录复制检查覆盖完整树、空目录、多操作共享父目录、隐藏和敏感项、相对与悬空链接、目录链接、目录及链接修改时间、源新增子项、目标被抢占、未知暂存项、取消和暂存祖先替换。创建结果、发布意图及发布结果的日志故障分别验证未知归属、已校验及已发布目录的只读诊断。Windows CI 另以不同卷验证完整目录复制。


## 隔离与恢复检查

隔离测试覆盖每授权根私有目录的零写入预览、逐项选择、保留期、完整目录、空目录、隐藏与敏感项、符号链接、硬链接、对象身份和权限保留。恢复测试覆盖当前授权、撤销后重新授权、原位置冲突改名、敏感范围重新确认、载荷变化、未知目录与已登记目录被替换。

故障注入分别在目录创建后、隔离移动后、恢复移动后和隔离条目事务中停止，验证源或载荷保留、后续项停止、完成事件与条目登记的事务一致性，以及只读诊断。恢复批次通过 `inverse_of` 关联原隔离操作。CLI 检查覆盖隔离列表、恢复预览与非交互执行拒绝。


## 撤销检查

撤销检查覆盖混合批次逆序、选择变更、同名冲突、原审计不变、重复撤销、后续操作依赖及逆序解除依赖、隔离与恢复的连续逆操作。副本检查覆盖原源已移走、完整目录及空目录、敏感内容重新确认，以及大小和修改时间均保持原值时的内容篡改；校验失败保留现有副本。复制证明按操作读取创建、验证与发布记录，独立于历史列表的事件分页。


## 永久删除检查

永久删除检查覆盖数量与敏感许可的组合确认、执行前新增项、完整目录及链接目标保持不变、按批清理隔离项、捕获后取消、第二条删除意图失败、删除后结果日志失败，以及部分删除后的显式尚存内容恢复。恢复诊断核对已确认移除数量、未确认意图和实际尚存清单，查询保持只读。

平台检查覆盖删除前替换保留替换对象，以及删除后的同步失败产生待核对结果。Windows 删除入口另做交叉编译检查，实际行为由原生 CI 运行。GUI 并行开发期间，后端检查在只包含 core、platform、cli 和对应锁文件的临时副本中执行。

## 元数据清单检查

元数据清单检查覆盖文件与目录的重复采集、扩展属性名称与大小、Windows 命名流描述、源对象替换、悬空链接、权限变化和特权位识别。夹具核对源正文保持原值，描述中仅包含附属数据的名称及大小。macOS 的四项用例已通过；Windows 分支通过交叉编译与 Clippy 检查，原生用例由三平台 CI 执行。

## 迁移载荷检查

迁移载荷检查覆盖正文与附属数据逐字节比较、只读权限保留、元数据版本变化、目标冲突、取消、原子发布和空暂存目录清理。macOS 用例包含跨块资源叉；Windows 原生用例另覆盖 NTFS 命名流、稀疏和压缩文件。macOS 三项用例及 Windows 交叉编译、Clippy 检查已通过，原生平台行为由 CI 验证。

## 文件跨卷迁移检查

核心用例注入跨设备重命名结果，覆盖敏感正文及附属数据许可、完整迁移、同大小同修改时间的内容篡改拒绝、重新确认后的撤销、捕获原对象后取消、保留载荷恢复，以及源端移除结果写入失败时的只读诊断。macOS 三项用例和核心、CLI 的 Clippy 检查已通过。Windows 原生用例使用两个本地卷验证真实跨设备错误、命名流与往返撤销；由 CI 的授权文件操作步骤执行。
