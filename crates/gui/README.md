# File Tidy GUI

基于 Tauri 2、TypeScript 和 Vite 的本地图形界面，与 CLI 共用 Rust 核心库。界面提供文件浏览、空间分析、分类与查重、操作计划审核、目录授权、隔离区、执行历史和恢复诊断。

## 开发运行

需要仓库指定的 Rust 工具链、Node.js 22 或更新版本，以及平台对应的 Tauri 系统依赖。Linux 的依赖安装列表见 [GUI CI](../../.github/workflows/ci.yml)。

在仓库根目录启动前端开发服务器：

```sh
npm ci --prefix crates/gui
npm run dev --prefix crates/gui
```

保持该终端运行，在另一个终端的仓库根目录启动桌面窗口：

```sh
cargo run --locked -p file-tidy-gui
```

## 检查

在仓库根目录运行：

```sh
npm run typecheck --prefix crates/gui
npm test --prefix crates/gui
npm run build --prefix crates/gui
npm run check:csp --prefix crates/gui
cargo clippy -p file-tidy-gui --all-targets --locked -- -D warnings
cargo test -p file-tidy-gui --locked
```

macOS 和 Windows 默认跳过需要独立文件系统夹具的测试。运行这些用例时，将 `FILE_TIDY_TEST_ROOT` 指向受保护目录、敏感目录和项目树以外的独立测试目录，再使用 `cargo test -p file-tidy-gui --locked -- --include-ignored`。

## 本地打包

在 `crates/gui` 目录安装依赖后，用 Tauri CLI 构建应用。以下命令在 macOS 上生成 `.app`：

```sh
npm ci
npm run tauri -- build --bundles app -- --locked
```

构建安装包时，将 `--bundles app` 替换为当前平台的格式：macOS 为 `dmg`，Windows 为 `nsis`，Linux 为 `deb`。默认产物位于仓库根目录的 `target/release/bundle/`；指定 `--target` 后位于 `target/<target>/release/bundle/`。

## 下载与发布

[GitHub Releases](https://github.com/SiIverAsh/file_tidy/releases) 中，以 `file-tidy-gui-` 开头的是 GUI 安装包，以 `file-tidy-cli-` 开头的是终端程序。新发布流程提供以下 GUI 附件及各自的 `.sha256` 校验文件：

| 平台 | 文件名 |
| --- | --- |
| Apple Silicon macOS | `file-tidy-gui-<version>-aarch64-apple-darwin.dmg` |
| Intel macOS | `file-tidy-gui-<version>-x86_64-apple-darwin.dmg` |
| Windows x64 | `file-tidy-gui-<version>-x86_64-pc-windows-msvc-setup.exe` |
| Linux x64 | `file-tidy-gui-<version>-x86_64-unknown-linux-gnu.deb` |

Release 工作流在标签提交通过 CI、安全检查以及 CLI / GUI 全部构建后，统一创建同一个 GitHub Release。标签必须包含 GUI 和相应发布配置。已有的 `v0.1.0` Release 仅提供 CLI，不会因更新工作流而自动增加 GUI 附件；新版本发布步骤见 [CI 与发布说明](../../docs/ci-cd.md)。

macOS 安装包暂使用临时签名（ad-hoc），尚未配置 Apple Developer ID 签名和公证。确认下载来源可信后，可在“系统设置 → 隐私与安全性”中选择“仍要打开”。

`src-tauri/gen/` 和 `src-tauri/permissions/autogenerated/` 由 Tauri 构建时生成；手写权限白名单保存在 `src-tauri/capabilities/default.json`。
